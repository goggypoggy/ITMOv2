# E2E-проверки

| Сценарий пользователя | Предусловия | Действие | Наблюдаемый результат | Подтверждение |
|---|---|---|---|---|
| Позитивный: корректный вход и формат ответа | Есть unified diff одного PR; размер ≤ 20000 символов; доступен POST /api/reviews | Отправить POST /api/reviews с diff | Ответ соответствует OUT-1: JSON со summary, risks (≤3) и checks; по QA-1 у каждого риска заполнены file, line, evidence | Ответ сервиса; парсер OUT-1 (context.md: OUT-1, QA-1) |
| Негативный: таймаут внешнего LLM | Смоделирована задержка внешнего LLM > 10 с | Выполнить запрос | Контролируемая ошибка по REL-1, без 5xx; время ожидания ≤ 10 с | Ответ сервиса; логи статуса (context.md: REL-1) |
| Граничный: превышение лимита размера | Размер diff > 20000 символов | Отправить POST /api/reviews с diff | HTTP 413 по API-1 | Ответ сервиса (context.md: API-1) |
| Позитивный: удаление секретов перед LLM | diff содержит тестовый секрет (token) | Отправить POST /api/reviews (LLM замокан) | Перед запросом к внешнему LLM секреты удалены/заменены на [REDACTED] | Перехват исходящего запроса к мок‑LLM (context.md: SEC-1; adr.md: исключить секреты) |
| Позитивный: отсутствие логирования содержимого | Включено логирование request_id/длительности/статуса | Выполнить POST /api/reviews | В логах нет diff/ответа; только request_id, длительность и статус | Логи сервиса (context.md: OBS-1) |
| Позитивный: отсутствие внешних действий | Запрещены внешние действия (GitHub) | Выполнить POST /api/reviews | Сервис не выполняет approve/merge/коммиты; только советы | Отсутствие внешних вызовов; состав ответа (context.md: SCOPE-1; adr.md: запрет внешних действий) |
| Негативный: риск без evidence | LLM возвращает риск без evidence | Выполнить POST /api/reviews | Риски без evidence не включаются | Ответ сервиса (context.md: QA-1; analysis.md: каждый риск с evidence) |
| Негативный: число рисков > 3 | LLM возвращает более 3 рисков | Выполнить POST /api/reviews | Итоговый массив рисков ≤ 3 | Ответ сервиса (context.md: OUT-1; adr.md: максимум три риска) |

## Источник

- Основной контекст правил: practices/practice_01/context.md (SEC-1, API-1, REL-1, OUT-1, SCOPE-1, QA-1, OBS-1)
- Подтверждения архитектурного контракта: practices/practice_01/adr.md (исключить секреты, максимум 3 риска, логирование метаданных)
- Обоснование структуры и evidence: practices/practice_01/analysis.md (JSON OUT-1; каждый риск с evidence)
- Согласование сценария: practices/practice_01/product_management.md (валидный diff; негативный сценарий >20000 символов)
