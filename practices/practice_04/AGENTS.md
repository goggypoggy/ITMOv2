# Правила проекта: лэндинг «AI‑репетитор по программированию»

Этот документ читает агент и команда. Здесь собраны цели, требования, стек, структура и правила работы.

## Описание проекта

- Тип: одностраничный сайт (Single Page) без бэкенда.
- Тематика: лэндинг онлайн‑сервиса «AI‑репетитор по программированию».
- Цель: наглядно показать ценность сервиса и дать интерактивные элементы.
- Две демонстрационные фичи:
  1. Переключатель уровня (Новичок/Средний/Продвинутый) — изменяет программу обучения и цены в тарифах.
  2. Калькулятор времени обучения — по часам в неделю и цели возвращает ETA и краткий план.

## Технический стек

- HTML5 + CSS (без препроцессоров).
- Ванильный JavaScript (ES‑модули). Без фреймворков и сборщиков.
- Статический сервер для локального просмотра: `npx serve .` (Vercel serve).
  - Стандартная команда: `npx --yes serve -l 8080 .` (запускать из каталога `practices/practice_04`).
  - Если порт занят, можно указать другой через `-l <port>`.
  - Альтернативные варианты допустимы только при идентичном поведении.
- Тесты обязательны; линтеры не обязательны в рамках этого проекта. При необходимости используем минимальные инструменты без сборки.

Ограничение: сайт строго одностраничный — один `index.html` с подключёнными статическими ресурсами.

## Архитектура и структура

Минимальная структура внутри `practices/practice_04`:

```
index.html
src/
main.js                // Точка входа, инициализация и привязка событий
styles.css             // Базовые стили лэндинга
components/
    level-switcher.js    // Фича A: логика переключателя уровней
    time-calculator.js   // Фича B: логика калькулятора времени
data/
    catalog.js           // Описания модулей/куррикулума по уровням
    pricing.js           // Тарифы/цены по уровням
    goals.js             // Цели обучения и требуемое кол-во часов
assets/
icons/                 // Пиктограммы (по желанию)
```

Правила именования и кода:
- CSS — понятные классы, желательно BEM‑подобные. Без глобальных сбросов, только необходимое.
- JS — модульность: каждая фича в отдельном файле, экспорт функций `init…`, `render…`.
- Данные (уровни, тарифы, цели) — отдельные объекты/модули в `src/data`.
- Состояние — в памяти, без сохранения. Персистентность (LocalStorage) не требуется.

## Функциональные требования

Фича A: Переключатель уровня
- UI: переключатель из 3 состояний — `Новичок`, `Средний`, `Продвинутый`.
- При смене уровня обновляются:
  - список «модулей/тем» (короткие названия и бейдж сложности),
  - карточки тарифов (цена, краткое описание, CTA‑кнопка).
- Выбор уровня визуально отражается (активное состояние).
- Не требуется сервер и реальная оплата; только изменение контента на странице.

Фича B: Калькулятор времени обучения
- Входные данные:
  - Часы в неделю: `number` или `range` (1–40).
  - Цель: выпадающий список (например, «JS Junior», «Frontend Base», «Node Intro»).
- Расчёт:
  - Для каждой цели задано «требуемое число часов».
  - `ETA (недели) = ceil(требуемые_часы / часы_в_неделю)`.
- Вывод:
  - Число недель.
  - Короткий план/подсказка (например: «14 недель: основы JS → DOM → асинхронность»).
- Обновление — в реальном времени при изменении входов.
- Валидация: часы вне диапазона (например, 0 или >40) не принимаются — показываем подсказку.

Нефункциональные требования
- Одностраничность: всё в `index.html`.
- Адаптивность: корректное отображение от 320px ширины.
- Производительность: без тяжёлых зависимостей; размер JS минимальный.

## План реализации (минимальный)

1. Каркас страницы (`index.html`):
   - Хедер с логотипом и навигацией по секциям (якоря).
   - Герой‑секция с описанием, CTA.
   - Секция «Программа» с контейнером для списка модулей.
   - Секция «Тарифы» с карточками (контейнер для динамики).
   - Секция «Калькулятор» с `input[type=range|number]`, `select`, областью результата.
   - Футер.

2. Данные (`src/data/*.js`):
   - `catalog.js` — словарь: уровень → массив модулей с полями `{title, badge}`.
   - `pricing.js` — уровень → тарифы `{name, price, features[]}`.
   - `goals.js` — цель → требуемые часы и краткий план.

3. Фича A (`level-switcher.js`):
   - Экспорт `initLevelSwitcher({ onChange })`.
   - При `onChange(level)` рендерим каталог и тарифы на основе данных.
   - В `main.js` инициализировать по умолчанию уровнем «Новичок».

4. Фича B (`time-calculator.js`):
   - Экспорт `initTimeCalculator()`.
   - Слушаем изменения `hoursPerWeek` и `goal`, считаем ETA, показываем результат.
   - Обрабатываем граничные значения (минимум/максимум) и понятные сообщения.

5. Стили (`styles.css`):
   - Базовая сетка, карточки, контролы, состояния фокуса/ховера.
   - Адаптив: стеки на мобильных, грида/флекс на десктопах.

## Критерии приёмки

- Переключатель уровня:
  - Три уровня доступны, выбранный визуально выделен.
  - При смене уровня меняются и «Программа», и «Тарифы».
  - Без перезагрузки страницы; без ошибок в консоли.

- Калькулятор времени:
  - Слайдер/поле часов и `select` работают и валидируются.
  - ETA корректно пересчитывается при каждом изменении.
  - Появляется краткий план для выбранной цели.

- Общие:
  - Один `index.html`, никаких переходов на другие страницы.
  - Базовая адаптивность (узкий/широкий экран).

## Правила работы с проектом

- Флоу задач:
  - Фича A делается первой и проверяется отдельно.
  - Фича B разрабатывается в отдельном worktree и затем проверяется в сборе с A.
- Гидлайны кода:
  - Без сторонних зависимостей и сборщиков.
  - Никаких инлайновых обработчиков (`onclick`); только через JS‑модули.
  - Минимизируем глобальные переменные, используем модульные скоупы.
- Git:
  - Коммиты атомарные: `feat: level switcher`, `feat: time calculator`, `style: base layout`.
  - Не смешивать рефакторинг и фичи в одном коммите.
- Папки/файлы:
  - Новые файлы ложатся в `src/…` по назначению.
  - Данные не «зашиваем» в HTML; используем `src/data`.

## Подсказки по проверке (ручные)

1. Запустить локальный сервер из `practices/practice_04`:
   - `npx --yes serve -l 8080 .`
   - Открыть `http://localhost:8080/`.
2. Переключить уровни и убедиться, что программа и тарифы меняются.
3. Изменять часы/цель — проверять обновление ETA и текста плана.
4. Открыть DevTools, проверить отсутствие ошибок.

## Инструкции для агента

- Прочитай этот файл перед началом работы.
- Задача A: реализовать `src/components/level-switcher.js` и соответствующие рендеры.

  - Проверка обработчиков: смена уровня изменяет текст в обоих блоках; изменение входов калькулятора меняет ETA.
  - MCP‑tool (если подключён) может валидировать схему данных `src/data/*` на наличие обязательных полей.
