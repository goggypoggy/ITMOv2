## Context Pack для первого рабочего сценария

### Факты и правила

- SEC-1: перед отправкой во внешний LLM из diff удаляются токены, пароли и приватные ключи.
- API-1: diff длиннее 20 000 символов отклоняется с HTTP 413.
- REL-1: таймаут внешнего LLM‑вызова 10 секунд; ошибка преобразуется в контролируемый ответ.
- OUT-1: ответ содержит summary, массив risks (≤3) и массив checks; у риска есть file, line, evidence, risk.
- SCOPE-1: сервис только советует; не пишет код и не выполняет действия в GitHub.
- QA-1: в ответ включаются только риски, подтверждённые строкой diff или правилом.
- OBS-1: в логах только request_id, длительность и статус; diff/ответ не логируются.

### Формат входа и результата

- Вход: unified diff одного PR (`TRAINING_PR.diff`).
- Результат: JSON по OUT-1.

### Ограничения и запрещённые действия

- Запрещено выполнять действия в GitHub; запрещено включать секреты в prompt/лог; нельзя выходить за рамки Context Pack.

### Хороший пример

app/review_service.py:19–22 — diff отправляется во внешний LLM без удаления секретов, что нарушает SEC-1. Проверка: передать diff с тестовым token и убедиться, что в prompt вместо токена — [REDACTED].
### Плохой пример

«Код можно улучшить. Добавьте тесты и обработку ошибок.» — без конкретного файла/строки и evidence.
### Что пока неизвестно

- Версия Python и клиент LLM (sync/async), требования к аутентификации, политика хранения артефактов проверок.
