6. Собственный MCP‑tool
   - Скрипт проверки схем данных оформлен и как CLI, и как экспорт: `scripts/validate-data.mjs`.
   - MCP‑server (стрим по stdio): `mcp/validate-data/server.mjs`.
     - Инструмент `validateDataSchemas(simulateError?: boolean)`.
     - Возвращает диагностический текст; при ошибках — isError=true.
   - Регистрация в `opencode.json` в разделе `mcp.validateData`. Агент может вызвать tool напрямую через MCP.
   - Команды: `npm run validate:data` — успешная проверка; `npm run validate:data:fail` — демонстрация ошибочного запуска.
   - Хук вызывает проверку автоматически до тестов.

   Обоснование подключений MCP:
   - validateData (собственный MCP): выносит проверку схем данных в внешний инструмент, доступный агенту независимо от исполнения JS‑кода страницы. Это даёт раннюю и воспроизводимую диагностику регрессий в `src/data/*`, а также единый интерфейс вызова (через MCP) для агентов и хуков.
   - Playwright MCP: обеспечивает возможность триггера e2e‑прогонов агентом через MCP‑tool в тех сценариях, где запуск тестов должен инициироваться не локальным скриптом, а внешним оркестратором. В данном проекте тесты запускаются через `npm test`, а MCP Playwright оставлен подключённым для совместимости и демонстрации интеграции.

7. Как запустить
   - Локально: `npx --yes serve -l 8080 .` (из каталога `practices/practice_04`), открыть `http://localhost:8080/`.
   - Тесты: сначала `npx playwright install`, затем `npm test`.
